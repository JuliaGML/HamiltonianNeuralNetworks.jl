Generalized Hamiltonian Neural Network

A generalized Hamiltonian neural network (GHNN) [3] learns a Hamiltonian system as a composition of symplectic-Euler steps rather than as the symplectic gradient of a scalar network. One step splits the state into $q$ and $p$ and changes one of the two by the gradient of an energy that depends on the other:

\[\begin{pmatrix} q \\ p \end{pmatrix} \mapsto \begin{pmatrix} q + \nabla_p T(p) \\ p \end{pmatrix} \quad\text{or}\quad \begin{pmatrix} q \\ p \end{pmatrix} \mapsto \begin{pmatrix} q \\ p - \nabla_q V(q) \end{pmatrix},\]

where $T$ is a learned kinetic and $V$ a learned potential energy. A chain of $n$ such pairs is a symplectic map from the state to the state one time step later, and it is the map that GeneralizedHamiltonianArchitecture learns.

Parameter dependence

Each energy network takes the parameters $\mu$ of the system beside the state it differentiates, so one network covers a range of problems instead of one problem instance. The forward pass is apply_parametric, reached as the functor nn(x, μ) of the NeuralNetwork built around the architecture, and a network trains on a ParametricDataLoader with ParametricLoss — the default loss train! takes for that loader.

using HamiltonianNeuralNetworks
using GeometricMachineLearning: NeuralNetwork, train!, TrainingOptimizer, Adam, Batch, ParametricDataLoader

μ = (m = 1.0, ω = 2.0)
nn = NeuralNetwork(GeneralizedHamiltonianArchitecture(2; parameters = μ))
nn([0.1, 0.2], μ)

The parameters an architecture holds are used for their shape: they fix the length of the flat vector that enters an energy network, and the values arrive with each call, one $\mu$ per sample.

Forcing and dissipation

ForcedGeneralizedHamiltonianArchitecture puts a ForcingLayer between the two steps of each integrator: a forcing enters the $\dot{p}$ equation, so it precedes the step that changes $p$. Its forcing_type names what the forcing reads — :Q, :P or :QP — as in ForcedSympNet.

The symbolic pullback

SymbolicPullback is the pullback of HNNLoss and takes a scalar Hamiltonian. A generalized Hamiltonian network is a map rather than a scalar Hamiltonian, so its pullback is SymbolicPullback(arch, ParametricLoss()), which generates the gradient of the parametric loss, and which train! takes as its loss.

For a GeneralizedHamiltonianArchitecture the pullback is composed layer by layer, by the layerwise sweep of SymbolicNeuralNetworks: fresh symbolic variables between two layers rather than one layer's expression inside the next. A SymplecticEuler step declares what it carries at that seam: the parameters of the system travel beside the state, flat, one column per sample, and are put back into their own shape there. Each step is then generated code of its own, and a chain of any number of integrators builds.

A ForcedGeneralizedHamiltonianArchitecture holds a ForcingLayer between two steps, which declares no such seam, so its pullback is one expression for the whole chain. Each step inlines the generated gradient of its energy network, and such an expression then holds one copy of it per integrator, each inside the next, so a forced chain of more than one integrator is refused. train! takes a ZygotePullback of the same loss by default, which has no such limit.

Library Functions

HamiltonianNeuralNetworks.GeneralizedHamiltonianArchitecture — Type
GeneralizedHamiltonianArchitecture <: HamiltonianArchitecture

A realization of generalized Hamiltonian neural networks (GHNNs) as introduced in [3].

The architecture is a chain of n_integrators pairs of symplectic-Euler steps, 2 n_integrators steps in all: each pair differentiates a learned kinetic and a learned potential energy. Its forward pass takes the parameters of the system beside the state:

nn(x, μ)

where x is a (q, p) pair or a stacked state and μ the parameters of the system, as apply_parametric takes them. This is what makes one network cover a range of problems rather than one problem instance.

Also see StandardHamiltonianArchitecture and ForcedGeneralizedHamiltonianArchitecture.

Constructor

The constructor takes the following input arguments:

  1. dim: system dimension, which is even,
  2. width = dim: width of the hidden layer. By default this is equal to dim,
  3. nhidden = 1: the number of hidden layers of each energy network,
  4. n_integrators = 1: the number of integrators used in the GHNN,
  5. activation = AbstractNeuralNetworks.TanhActivation(): the activation function used in the GHNN,
  6. parameters = NullParameters(): the parameters of the system, which fix the length of the flat vector the energy networks take beside their state; their values enter with each call.

The parameter count

One integrator holds two energy networks, one kinetic and one potential, and neither is shared, so the network has 2 n_integrators of them. Each is a first dense layer over dim ÷ 2 + |\mu| rows and width columns, nhidden hidden layers of width width, and a biasless Linear(width, 1), so the whole network has

\[2\,n_\mathrm{integrators}\left[(\mathrm{dim}/2 + |\mu| + 1)\mathrm{width} + \mathrm{nhidden}\,\mathrm{width}(\mathrm{width} + 1) + \mathrm{width}\right]\]

parameters. The thesis counts the first dense layer among the hidden layers, i.e. as nhidden + 1 of them.

HamiltonianNeuralNetworks.ForcedGeneralizedHamiltonianArchitecture — Type
ForcedGeneralizedHamiltonianArchitecture <: HamiltonianArchitecture

A GeneralizedHamiltonianArchitecture with a non-conservative term — a forcing or a dissipation — in each of its integrators.

Each integrator is a SymplecticEulerA step, a ForcingLayer, and a SymplecticEulerB step, in that order: the forcing acts on $\dot{p}$, so it precedes the step that changes $p$. Also compare ForcedSympNet.

Constructor

The constructor takes the arguments of GeneralizedHamiltonianArchitecture and

  1. n_forcing_layers = 2: the number of hidden layers of the network of each forcing layer,
  2. forcing_type = :P: what the forcing reads, :Q, :P or :QP; see ForcingLayer.

HamiltonianNeuralNetworks.SymbolicEnergy — Type
SymbolicEnergy

The learned energy of one half of a symplectic-Euler step: the shape of the energy network over the state it differentiates and the parameters of the system, from which Chain builds the network and build_gradient the gradient that the step calls.

parameter_length and parameter_layout are the shape of those parameters: the length of their flat vector, which is what the first layer of the network adds to its input, and the layout that puts such a vector back into the shape of μ. The names are ParametricResNetLayer's, which carries the same pair for the same reasons.

A system whose parameters flatten to no entries — NullParameters(), NamedTuple() or a NamedTuple of empty arrays — has the layout of NullParameters(), which is how a SymplecticEuler step built from it knows that it carries nothing.

See SymbolicPotentialEnergy and SymbolicKineticEnergy.

source
HamiltonianNeuralNetworks.SymbolicPotentialEnergy — Type
SymbolicPotentialEnergy

The potential energy of a generalized Hamiltonian network, $V$ in the Hamiltonian $H = T(p) + V(q)$ of a mechanical system. One SymplecticEulerB step differentiates it with respect to $q$.

The constructor is SymbolicPotentialEnergy(dim, width, nhidden, activation; parameters), where dim is the full phase-space dimension, which is even: the network takes the dim ÷ 2 rows of $q$ and the flattened parameters of the system below them.

Also see SymbolicKineticEnergy.

HamiltonianNeuralNetworks.build_gradient — Function
build_gradient(se::SymbolicEnergy)

Build the function that evaluates the gradient of se's energy with respect to the state it differentiates.

The generated function takes the state with the flattened parameters of the system below it — the input the energy network of se takes — and the network parameters, and returns a vector with the dim ÷ 2 rows of the gradient. It is built once per layer, so that a step of a layer is one call of generated code rather than a differentiation of its energy network.

Only the first dim ÷ 2 entries of the input are differentiated: the entries after them are the parameters of the system, which are not.

The generated function is built with inplace = false, so that a caller can differentiate through a step of the layer with Zygote.

HamiltonianNeuralNetworks.SymplecticEuler — Type
SymplecticEuler

One step of the symplectic Euler integrator of a generalized Hamiltonian network, built from a SymbolicEnergy.

A step splits the state into q and p and changes one of the two by the gradient of the energy of the other:

\[\begin{pmatrix} q \\ p \end{pmatrix} \mapsto \begin{pmatrix} q + \nabla_p T(p, \mu) \\ p \end{pmatrix} \quad\text{or}\quad \begin{pmatrix} q \\ p - \nabla_q V(q, \mu) \end{pmatrix},\]

for the SymplecticEulerA and SymplecticEulerB constructors.

Implementation

The gradient is the gradient_function that build_gradient generated for the energy network, which the layer stores beside the network itself. A step is one call of it, and the parameters of the network are the parameters of energy_model: they nest one level deeper than the layer's own, as for every layer that holds a model.

It also carries the shape of the parameters of the system — their flat length, and the layout that puts a flat vector of them back into the shape of μ. The layerwise SymbolicPullback of SymbolicNeuralNetworks carries those parameters flat across the seam between two layers, and this is what the layer reassembles them with. The layout is the last type parameter, so that the partial signatures of SymplecticEulerA and SymplecticEulerB go on matching with the layout left free. The layout's type also says whether the layer carries anything across that seam: a system without parameters has the empty layout, so the number of arguments the seam hands the generated kernels is fixed by the layer's type.

SymbolicNeuralNetworks.SymbolicPullback — Method
SymbolicPullback(arch, ::ParametricLoss)

Make a SymbolicPullback of ParametricLoss for a GeneralizedHamiltonianArchitecture or a ForcedGeneralizedHamiltonianArchitecture, whose forward pass takes the parameters of the system. train! takes it as its loss.

Its value is ParametricLoss on the batch, and its gradient is the gradient of that value. On a stacked batch the value is $\ell = \|R\|/\|Y\|$ with $R = \mathrm{NN}(X, \mu) - Y$, and on a (q, p) batch it is $\ell = (\|R_q\| + \|R_p\|)/(\|Y_q\| + \|Y_p\|)$ — each half scaled by its own norm, which is what the loss does with a (q, p) pair. The gradient has the parameters' element type, and a zero residual gives a zero gradient.

The batch

The pullback takes what a ParametricDataLoader draws: an input and an output of $2d \times 1 \times k$ with $k$ values of $\mu$, one per sample, or a (q, p) pair of $d \times 1 \times k$. A matrix with one $\mu$ is not one of the forms apply_parametric takes.

The construction

The parameters of the system that arch holds fix the shape of $\mu$; their values enter with each call, one per sample.

For a GeneralizedHamiltonianArchitecture the pullback is composed layer by layer, by the layerwise sweep of SymbolicNeuralNetworks: each SymplecticEuler step gets generated code of its own, and the parameters of the system cross between two steps beside the state. So the expression a step is built from holds that step alone, and any number of integrators builds. At a call the sweep is seeded with the cotangent of the loss at the output — the residual of each half, scaled by the two norms the value divides by — so the gradient of the batch comes out of one backward pass.

For a ForcedGeneralizedHamiltonianArchitecture the sweep does not apply, because the ForcingLayer of its chain declares no seam for it. The pullback is then built from one expression for the whole chain, the generated per-sample gradient of $\tfrac12\|r_i\|^2$ for each half, which is scaled at a call the same way. That expression holds one copy of each step's generated gradient inside the next, so it grows multiplicatively with the number of integrators, and a forced architecture with n_integrators > 1 is an ArgumentError; ZygotePullback(ParametricLoss()), which is what train! takes by default, trains it.

SymbolicPullback(arch::HamiltonianArchitecture) is the pullback of HNNLoss and keeps its signature; a generalized architecture is refused there.
